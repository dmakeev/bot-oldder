# Техническая спецификация: Telegram-бот «PROсрочка» (MVP)

## 1. Общее описание

Бот-помощник для юриста по банкротству: расчёт и напоминание о процессуальных сроках, ведение справочника, работа с делами о банкротстве и арбитражными спорами.

**Целевая аудитория:** юристы, специализирующиеся на делах о банкротстве юридических и физических лиц.

**Основная ценность:** автоматизация расчёта процессуальных сроков и напоминание о важных датах, исключение человеческих ошибок при работе с множеством дел.

## 2. Функциональные требования

### 2.1. Доступы (одобрение Олегом)

- Новый пользователь нажимает «Старт» → бот отправляет запрос Олегу в личку
- Олег нажимает [Разрешить] или [Запретить]
- Если запрещено, бот пишет пользователю «Нет доступа»
- Олег видит список всех пользователей с кнопкой [Отозвать]
- При отзыве доступа бот пишет пользователю, что доступ закрыт

### 2.2. Проекты

**Типы проектов:**
1. Дело о банкротстве
2. Обособленный спор
3. Арбитражный спор
4. Своё напоминание

**Дело о банкротстве:**
- Название проекта (обязательно)
- Номер дела (обязательно)
- Процедура(ы): наблюдение, финансовое оздоровление (ФО), внешнее управление (ВУ), конкурсное производство (КП), реструктуризация долгов, реализация имущества
- Дата введения процедуры (обязательно)

**Обособленный спор:**
- Название проекта (обязательно)
- Номер дела (обязательно)
- Привязка к делу о банкротстве (опционально)

**Арбитражный спор:**
- Название проекта (обязательно)
- Номер дела (обязательно)

**Своё напоминание:**
- Название (обязательно)
- Текст напоминания (обязательно)
- Дата и время (опционально)

**Управление проектами:**
- Создание проекта через пошаговый диалог
- Просмотр списка проектов (/projects)
- Редактирование проекта
- Удаление проекта с подтверждением

### 2.3. Собрания кредиторов (СК)

Три стадии:
1. **Срок «не позднее»:** бот сам ставит срок (1 раз в 3 месяца от введения процедуры или прошлого СК)
2. **Назначено на дату, время:** пользователь вводит дату и время
3. **Проведено:** пользователь отмечает проведение

Автоматическое создание цепочек напоминаний при назначении СК.

### 2.4. Судебные заседания

- Дата и время заседания (обязательно)
- Напоминания: за 2 недели, за 1 неделю, за 3 дня, за 1 день
- На следующий день после заседания бот спрашивает: [Отложено] / [Объявлен перерыв] / [Рассмотрено]
- При отсутствии ответа бот спрашивает каждый день

### 2.5. Обжалование

- По запасному правилу: 1 месяц от даты изготовления акта в полном объёме
- Обособленные споры: 10 дней (ст. 11.11 справочника)
- Обжалование в апелляции → кассации → надзор
- Если источники расходятся, бот спрашивает администратора

### 2.6. Публикации в ЕФРСБ

- Расчёт срока оплаты (срок минус 1 р.д.)
- «Узнал о факте» = дата публикации на kad.arbitr.ru
- Напоминания: сразу, за 1 день, срок оплаты

### 2.7. «Суд обязал представить» (1.25)

- Что: объяснения / отзыв / документы / другое (кнопками)
- Срок: конкретная дата из определения, или «за N дней до заседания»
- Если срок не указан: условный срок за 5 р.д. до заседания с пометкой «условный»
- Напоминания по умолчанию

### 2.8. Производственный календарь

- Праздничные дни 2026 и 2027 (согласно справочнику)
- Переносы выходных
- Обработка сроков, выпадающих на выходные
- Напоминание администратору о необходимости обновления календаря на следующий год

### 2.9. Напоминания и утренняя сводка

- Утренняя сводка в 09:09 МСК
- Кнопки [Сделано], [Отменить], [Больше не напоминать]
- Альтернативные пункты (уведомление почтой/иным способом)
- Отмена цепочек при [Отменить] у назначенного СК
- «Горит» - статус после последнего напоминания

### 2.10. Поиск по справочнику

- Поиск по ключевым словам с учётом словоформ и синонимов
- Вывод результатов с нормой, отсчётом, режимом
- Обработка нескольких совпадений
- «В моём справочнике этого нет» если не найдено

### 2.11. Таблицы и Excel

- Таблица по проекту в чате
- Экспорт в Excel
- Выборки: проект/все, впереди/прошедшее/всё, за период, горящее/просроченное

## 3. Нефункциональные требования

### 3.1. Производительность

- Отклик на команды: < 1 секунда
- Отправка утренней сводки: < 10 минут после 09:09
- Расчёт дат: < 1 секунда

### 3.2. Надёжность

- Персистентность данных между перезапусками
- Восстановление напоминаний после перезапуска
- Обработка ошибок Telegram API

### 3.3. Безопасность

- Токен бота хранится в .env (не в репозитории)
- Раздельное хранилище для каждого чата
- Администратор видит только названия групп, не содержимое

### 3.4. Поддержка

- Справочник легко обновлять без перезапуска бота
- Логирование всех операций
- Простая диагностика через логи

### 4.2. Хранение данных

**SQLite** с асинхронным драйвером (aiosqlite).

**Структура таблиц:**

```sql
CREATE TABLE chats (
    chat_id INTEGER PRIMARY KEY,
    type TEXT NOT NULL, -- 'private' or 'group'
    name TEXT
);

CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chat_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    case_number TEXT NOT NULL,
    type TEXT NOT NULL, -- 'bankruptcy', 'related_dispute', 'arbitration', 'custom'
    procedures TEXT, -- JSON array for bankruptcy projects
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    active BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (chat_id) REFERENCES chats(chat_id)
);

CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    type TEXT NOT NULL, -- 'meeting', 'hearing', 'appeal', 'publication', 'court_order'
    scheduled_at TIMESTAMP NOT NULL,
    status TEXT NOT NULL DEFAULT 'upcoming', -- 'upcoming', 'done', 'cancelled'
    data TEXT, -- JSON with event-specific data
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

CREATE TABLE reminders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_id INTEGER NOT NULL,
    scheduled_at TIMESTAMP NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending', -- 'pending', 'sent', 'done', 'cancelled'
    FOREIGN KEY (event_id) REFERENCES events(id)
);

CREATE TABLE user_access (
    chat_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending', -- 'pending', 'approved', 'revoked'
    approved_by INTEGER,
    approved_at TIMESTAMP,
    PRIMARY KEY (chat_id, user_id)
);
```

### 5.2. Правила расчёта

- Сроки по ЗоБ: календарные дни, если не указано «р. д.» (рабочие дни)
- Сроки по АПК: нерабочие дни не включаются (ч. 3 ст. 113 АПК)
- Если срок по АПК заканчивается на нерабочий день, переносится на первый рабочий (ч. 4 ст. 114 АПК)
- Дата изготовления в полном объёме = дата принятия акта (ч. 2 ст. 176 АПК)

## 6. Логика напоминаний

### 6.1. По умолчанию

- Срок > 10 дней: сразу после ввода; за 2 недели (если до срока больше 2 недель); за 7 дней; за 3 дня; за 1 день
- Срок ≤ 10 дней: сразу; за 7 дней; за 3 дня; за 1 день
- В ЛЮБОЙ схеме обязательно за 7 дней, за 3 дня и за 1 день

### 6.2. Выходные

- Напоминание «за N до срока» выпало на нерабочий день: приходит в ближайший рабочий день ДО него
- «Сразу» в начале периода выпало на нерабочий день: приходит в первый рабочий день ПОСЛЕ
- «За 1 день»: текст «Завтра, ДД.ММ[, ЧЧ:ММ]: <действие>. <Проект>». Если завтра нерабочий день, напоминание приходит в предыдущий рабочий день, вместо «Завтра» день недели
- Срок по ЗоБ выпал на нерабочий день (дата НЕ сдвигается, рядом пометка «Выходной!»)
- Срок по АПК выпал на нерабочий день (переносится на следующий рабочий по ч. 4 ст. 114 АПК)

### 6.3. Кнопки

- [Сделано] - следующие напоминания по этому сроку отменяются, статус «выполнено»
- [Отменить] - с подтверждением, отменяет напоминание
- [Больше не напоминать] - с подтверждением, убирает пункт совсем
- У повторяющихся пунктов [Отменить] снимает только текущий период

## 12. Критерии приёмки (MVP)

Бот готов к выдаче, когда:
- [ ] Создание проекта любого типа работает
- [ ] Напоминания создаются по логике справочника
- [ ] Утренняя сводка отправляется в 09:09 МСК
- [ ] Кнопки [Сделано], [Отменить], [Больше не напоминать] работают
- [ ] Обработка выходных дней и праздников корректна
- [ ] Поиск по справочнику работает
- [ ] Экспорт в Excel работает
- [ ] Все автотесты проходят (покрытие ≥ 90%)
